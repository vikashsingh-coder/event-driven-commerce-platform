# Phase 0.4.9 — Environment Configuration

## 1. Configuration Architecture

Our final configuration flow:

```text
                  Environment
                      │
             ┌────────┴────────┐
             │                 │
          Local               CI/CD
             │                 │
             └────────┬────────┘
                      ▼
                 process.env
                      │
                      ▼
             Configuration Loader
                      │
                      ▼
                Validation
                      │
              ┌───────┴───────┐
              │               │
             Valid          Invalid
              │               │
              ▼               ▼
       Typed AppConfig       Exit
              │
              ▼
          Application
```

If configuration is invalid, the service should **fail fast during startup**.

---

# 2. Configuration Principles

We will follow these rules:

```text
1. No secrets committed to Git
2. No process.env scattered across services
3. Validate configuration at startup
4. Strongly type configuration
5. Each service gets only required configuration
6. Production secrets come from deployment infrastructure
7. .env.example documents required variables
8. Test configuration is isolated
9. Configuration names are consistent
10. Fail fast when required configuration is missing
```

# 19. Parsing Configuration

import { orderServiceEnvSchema } from "./schema";

export function loadOrderServiceConfig() {
  const result = orderServiceEnvSchema.safeParse(process.env);

  if (!result.success) {
    console.error("Invalid environment configuration:", result.error.flatten());

    process.exit(1);
  }

  return result.data;
}
