# 6. `app.ts` vs `server.ts`

This is an important architectural decision.

### `app.ts`

Responsible for building Express:

```text
Express
+
Middleware
+
Routes
+
Error handling
```

### `server.ts`

Responsible for:

```text
Database connection
Redis connection
RabbitMQ connection
HTTP server
Graceful shutdown
```

So:

```text
app.ts
    ↓
Express Application
```

while:

```text
server.ts
    ↓
Infrastructure
    ↓
HTTP Server
```

This separation makes testing much easier.

# 14. Request ID Middleware

Every incoming request gets a request ID.

Example:

```text
Client
  │
  │ X-Request-ID
  ▼
Nginx
  │
  ▼
Service
```

If the client doesn't provide one, the service generates it.

Example:

```typescript
import { randomUUID } from "node:crypto";

export function requestIdMiddleware(req: any, res: any, next: any) {
  const requestId = req.headers["x-request-id"] ?? randomUUID();

  req.requestId = requestId;

  res.setHeader("X-Request-ID", requestId);

  next();
}
```

Later we'll improve this with proper TypeScript request typing.


# 28. Graceful Shutdown

This is mandatory.

When Docker sends:

```text
SIGTERM
```

we do:

```text
SIGTERM
  │
  ▼
Stop accepting requests
  │
  ▼
Stop RabbitMQ consumers
  │
  ▼
Finish active requests
  │
  ▼
Close Redis
  │
  ▼
Close database
  │
  ▼
Close HTTP server
  │
  ▼
Exit
```

Without graceful shutdown, we risk:

- Lost messages
- Partial operations
- Connection leaks
- Failed deployments

---

# 29. Graceful Shutdown Skeleton

```typescript
async function shutdown() {
  console.log("Shutting down...");

  server.close();

  await rabbitmq.close();

  await redis.quit();

  await database.disconnect();

  process.exit(0);
}

process.on("SIGTERM", shutdown);

process.on("SIGINT", shutdown);
```

We'll later make this robust against repeated signals and shutdown errors.

# 44. Service-to-Service Communication

We have two mechanisms.

### Synchronous

HTTP:

```text

 ↓ HTTP

```

Use when an immediate response is required.

### Asynchronous

RabbitMQ:

```text
Order
 ↓
RabbitMQ
 ↓

```

Use for events and decoupled workflows.

We should avoid turning every service interaction into HTTP.

# 45. Service Template Golden Rules

Our services will follow:

```text
1. No business logic in routes
2. No database queries in controllers
3. No process.env throughout application code
4. No console.log for application logging
5. No direct database access from another service
6. No shared business logic package
7. No secrets in source code
8. No unvalidated external input
9. No unhandled promise rejections
10. No abrupt process.exit during normal operation
```
