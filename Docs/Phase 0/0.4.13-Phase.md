# 4. CI Pipeline

Create:

```text
.github/workflows/ci.yml
```

Basic structure:

```yaml
name: CI

on:
  push:
    branches:
      - main
      - develop

  pull_request:
    branches:
      - main
      - develop

jobs:
  quality:
    name: Code Quality
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup pnpm
        uses: pnpm/action-setup@v4
        with:
          version: 10

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: pnpm

      - name: Install dependencies
        run: pnpm install --frozen-lockfile

      - name: Format check
        run: pnpm format:check

      - name: Lint
        run: pnpm lint

      - name: Typecheck
        run: pnpm typecheck

      - name: Unit tests
        run: pnpm test:unit

      - name: Build
        run: pnpm build
```

The exact Node/pnpm versions should match the versions we standardize in the repository.

---

# 5. Why `--frozen-lockfile`?

CI should **never silently modify dependency versions**.

Use:

```bash
pnpm install --frozen-lockfile
```

instead of:

```bash
pnpm install
```

This guarantees that CI uses the exact dependency graph represented by:

```text
pnpm-lock.yaml
```

If someone changes:

```text
package.json
```

without updating the lockfile, CI fails.

That's desirable.

# 10. Infrastructure Startup

Example CI step:

```yaml
- name: Start infrastructure
  run: docker compose up -d
```

Then:

```yaml
- name: Check infrastructure
  run: docker compose ps
```

We should **not** assume `docker compose up -d` means everything is ready.

Containers can be running while PostgreSQL/RabbitMQ/etc. are still initializing.

That's why our health checks from **0.4.10** matter.

# 18. CI Job Architecture

Rather than one giant job, use separate jobs where useful:

```text
                    ┌── quality
                    │
Git Push ───────────┼── unit-test
                    │
                    ├── build
                    │
                    └── integration
```

Integration should depend on the basic quality checks.

For example:

```yaml
needs:
  - quality
  - unit-tests
  - build
```

This avoids running expensive integration tests when TypeScript doesn't even compile.
