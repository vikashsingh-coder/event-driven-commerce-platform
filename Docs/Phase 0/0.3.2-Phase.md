# Phase 0.3.2 — Logger Package Implementation

## Goal

Create a centralized logging package that will be used by every microservice.

In a distributed system, debugging becomes difficult because requests move across multiple services:

```text
User Request

    |

Nginx

    |

Auth Service

    |

Order Service

    |

Payment Service

    |

Notification Service
```

We need a common logging format so we can trace:

- Which service generated the log
- Which request generated the log
- Which user/order/payment was involved
- Error details
- Execution time

---

# Logger Technology Decision

We will use:

```text
Pino Logger
```

Why Pino?

- Extremely fast
- JSON structured logging
- Production-ready
- Works well with Node.js microservices
- Supports log aggregation tools

# 6. Logger Serializers

Create:

```
packages/logger/src/serializers.ts
```

Purpose:

Remove sensitive information from logs.

Never log:

- Password
- JWT token
- Payment credentials

```typescript
export const serializers = {
  error(error: Error) {
    return {
      name: error.name,

      message: error.message,

      stack: error.stack,
    };
  },

  request(request: any) {
    return {
      method: request.method,

      url: request.url,

      ip: request.ip,
    };
  },

  user(user: any) {
    return {
      id: user.id,

      email: maskEmail(user.email),
    };
  },
};

function maskEmail(email?: string) {
  if (!email) {
    return undefined;
  }

  const [name, domain] = email.split("@");

  return `${name[0]}***@${domain}`;
}
```

# 7. Logger Implementation

Create:

```
packages/logger/src/logger.ts
```

```typescript
import pino from "pino";

import { env } from "@ecommerce/config";

const isDevelopment = env.NODE_ENV === "development";

export const logger = pino({
  level: isDevelopment ? "debug" : "info",

  base: {
    service: env.SERVICE_NAME,
  },

  timestamp: pino.stdTimeFunctions.isoTime,

  transport: isDevelopment
    ? {
        target: "pino-pretty",

        options: {
          colorize: true,

          translateTime: "SYS:standard",
        },
      }
    : undefined,
});
```

# 10. Logging Levels

We will follow:

| Level | Usage                      |
| ----- | -------------------------- |
| fatal | Application crash          |
| error | Errors requiring attention |
| warn  | Warning situations         |
| info  | Normal business events     |
| debug | Development debugging      |
| trace | Detailed debugging         |
