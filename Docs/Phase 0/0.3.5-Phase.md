# Phase 0.3.5 — Database Package

Now we build the shared database foundation.

One important architectural decision first: **we should not create one generic database abstraction that hides PostgreSQL and MongoDB behind the same API.** They have different transaction and query models.

For this project:

```text
PostgreSQL
    ↓
Prisma
    ↓
@ecommerce/database

MongoDB
    ↓
Mongoose
    ↓
@ecommerce/database
```

The shared package will provide **connection management and clients**, while each service owns its models/repositories.

---

# 1. Database Allocation

Based on our architecture, we'll use:

| Service              | Database   | Reason                            |
| -------------------- | ---------- | --------------------------------- |
| Auth Service         | PostgreSQL | Users, roles, permissions         |
| Product Service      | MongoDB    | Flexible product/catalog data     |
| Inventory Service    | PostgreSQL | Strong consistency + transactions |
| Order Service        | PostgreSQL | ACID transactions                 |
| Payment Service      | PostgreSQL | Financial records                 |
| Notification Service | MongoDB    | Flexible notification documents   |
| Analytics Service    | PostgreSQL | Reporting/aggregation             |

Redis remains separate for caching/state.

```text
                    Database Layer
                         |
             ┌───────────┴───────────┐
             │                       │
        PostgreSQL                MongoDB
             │                       │
        Prisma Client           Mongoose
             │                       │
       ----------------      ----------------
       |      |      |      |              |
      Auth  Order Payment  Product    Notification
             |
         Inventory
             |
         Analytics
```

# 6. PostgreSQL Client

Create:

```text
packages/database/src/postgres/client.ts
```

```typescript
import { PrismaClient } from "@prisma/client";

export const prisma = new PrismaClient({
  log: [
    {
      emit: "event",
      level: "error",
    },
    {
      emit: "event",
      level: "warn",
    },
  ],
});

let isConnected = false;

export async function connectPostgres(): Promise<void> {
  if (isConnected) {
    return;
  }

  await prisma.$connect();

  isConnected = true;
}

export async function disconnectPostgres(): Promise<void> {
  if (!isConnected) {
    return;
  }

  await prisma.$disconnect();

  isConnected = false;
}
```

# 8. MongoDB Connection Events

We should monitor connection state.

Update:

```text
packages/database/src/mongodb/connection.ts
```

```typescript
import mongoose from "mongoose";

let isConnected = false;

export async function connectMongoDB(uri: string): Promise<void> {
  if (isConnected) {
    return;
  }

  mongoose.connection.on("connected", () => {
    console.info("MongoDB connected");
  });

  mongoose.connection.on("error", (error) => {
    console.error("MongoDB connection error", error);
  });

  mongoose.connection.on("disconnected", () => {
    console.warn("MongoDB disconnected");
  });

  await mongoose.connect(uri);

  isConnected = true;
}

export async function disconnectMongoDB(): Promise<void> {
  if (!isConnected) {
    return;
  }

  await mongoose.disconnect();

  isConnected = false;
}

export function getMongoConnection() {
  return mongoose.connection;
}
```

Later we will replace the direct `console` calls with our shared `@ecommerce/logger`.

# 12. Prisma Setup

There is an important distinction here.

The **shared package provides the Prisma client**, but each PostgreSQL service should eventually own its own schema/migrations.

We do **not** want:

```text
One giant Prisma schema
        ↓
All services
```

Instead:

```text
Auth Service
    ↓
Auth Prisma Schema
    ↓
Auth Database


Order Service
    ↓
Order Prisma Schema
    ↓
Order Database
```

This preserves microservice database ownership.

```text
   auth_db        order_db       payment_db
       │              │              │
       ↓              ↓              ↓

       ┌──────────────┼──────────────┐
       │              │
       ↓              ↓

       │              │
       ↓              ↓

```

This is much closer to a true microservice architecture than having every service directly share the same database tables.

```text
Docker → postgres
```

# 19. Graceful Shutdown

Microservices must close database connections when shutting down.

For PostgreSQL:

```typescript
process.on("SIGTERM", async () => {
  await disconnectPostgres();

  process.exit(0);
});
```

For MongoDB:

```typescript
process.on("SIGTERM", async () => {
  await disconnectMongoDB();

  process.exit(0);
});
```

Eventually we'll centralize application shutdown so every service doesn't duplicate this logic.

# 20. Database Transactions

PostgreSQL services will use Prisma transactions.

Example:

```typescript
await prisma.$transaction(async (transaction) => {
  const order = await transaction.order.create({
    data: orderData,
  });

  await transaction.orderItem.createMany({
    data: orderItems,
  });
});
```

This is important for:

```text
Order creation
Inventory reservation
Payment records
Refund processing
```

---

# 21. MongoDB Transactions

MongoDB supports transactions as well.

With Mongoose:

```typescript
const session = await mongoose.startSession();

try {
  await session.withTransaction(async () => {
    // Database operations
  });
} finally {
  await session.endSession();
}
```

However, we should **not automatically use MongoDB transactions everywhere**.

Use them when multiple documents must change atomically.

# 22. Important Microservice Rule

The database package should **not** contain business logic.

Bad:

```text
database/
└── createOrder()
```

Good:

```text
Order Service
│
├── Controller
├── Service
├── Repository
└── Database Client
```

The shared package provides:

```text
Connection
Client
Transaction capability
Database infrastructure
```

The service owns:

```text
Models
Repositories
Queries
Business rules
```

# 23. Repository Pattern

Eventually Order Service will look like:

```text
order-service/

├── prisma/
│   └── schema.prisma
│
└── src/
    ├── controllers/
    ├── services/
    ├── repositories/
    │   └── order.repository.ts
    ├── routes/
    └── schemas/
```

Repository:

```typescript
import { prisma } from "@ecommerce/database";

export class OrderRepository {
  async findById(id: string) {
    return prisma.order.findUnique({
      where: {
        id,
      },
    });
  }
}
```

The repository owns the query.

# 24. Database Error Handling

Database errors should not leak directly to clients.

For example:

```text
Prisma Error
    ↓
Repository
    ↓
Service
    ↓
AppError
    ↓
Error Handler
    ↓
Client
```

Example:

```typescript
try {
  return await prisma.order.create({
    data,
  });
} catch (error) {
  throw new DatabaseError("Unable to create order", error);
}
```

We'll add dedicated database errors when we integrate the database package more deeply with `@ecommerce/errors`.
