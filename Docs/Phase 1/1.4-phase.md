# Phase 1.4 — Shared Redis Package

We’ll build `@ecommerce/redis` as the shared Redis infrastructure layer for your event-driven e-commerce backend.

The goal is to give each service a consistent way to connect to Redis, check its health, cache JSON data with TTLs, and shut down cleanly—without duplicating connection logic across services.

## 1. What we’re building

E-commerce services

Auth · Product · Order

`@ecommerce/redis`

Client lifecycle · JSON cache · TTL · Health checks

Redis

Shared infrastructure, separate service-specific keys

We’ll use ioredis for the Redis client and reuse the `@ecommerce/logger` and `@ecommerce/config` packages created in the previous phases.

The package will provide:

- A single reusable Redis client per service process.
- Connection, `PING` health check, and graceful close methods.
- Typed JSON cache helpers with explicit TTLs.
- Structured error logging without exposing connection URLs or cached values.
- Unit tests and commands to verify the package.

Design rule: Redis is a cache and infrastructure dependency—not the source of truth for orders, payments, or inventory. We’ll keep durable business state in the appropriate service database.

## 3. Implement the JSON cache

We'll keep cache behavior separate from connection management. That makes the cache helpers easier to test without requiring a running Redis server.

### Step 3 — `packages/redis/src/cache/create-json-cache.ts`

```

import type { Logger } from "pino";

export interface RedisCacheClient {
  get(key: string): Promise<string | null>;
  set(
    key: string,
    value: string,
    ...args: Array<string | number>
  ): Promise<string | null>;
  del(key: string): Promise<number>;
}

export interface JsonCacheOptions {
  ttlSeconds?: number;
}

export interface JsonCache {
  getJson<T>(key: string): Promise<T | null>;
  setJson<T>(
    key: string,
    value: T,
    options?: JsonCacheOptions
  ): Promise<void>;
  delete(key: string): Promise<void>;
}

function assertValidKey(key: string): void {
  if (typeof key !== "string" || key.trim().length === 0) {
    throw new Error("Cache key must be a non-empty string");
  }
}

function assertValidTtl(ttlSeconds: number | undefined): void {
  if (
    ttlSeconds !== undefined &&
    (!Number.isSafeInteger(ttlSeconds) || ttlSeconds <= 0)
  ) {
    throw new Error("ttlSeconds must be a positive integer");
  }
}

export function createJsonCache(
  client: RedisCacheClient,
  logger: Pick<Logger, "warn">
): JsonCache {
  return {
    async getJson<T>(key: string): Promise<T | null> {
      assertValidKey(key);

      const serialized = await client.get(key);

      if (serialized === null) {
        return null;
      }

      try {
        return JSON.parse(serialized) as T;
      } catch {
        // Treat malformed cache data as a miss. Never log its contents.
        logger.warn(
          { cacheKey: key },
          "Invalid JSON in Redis cache; evicting entry"
        );

        void client.del(key).catch(() => {
          logger.warn(
            { cacheKey: key },
            "Failed to evict invalid Redis cache entry"
          );
        });

        return null;
      }
    },

    async setJson<T>(
      key: string,
      value: T,
      options: JsonCacheOptions = {}
    ): Promise<void> {
      assertValidKey(key);
      assertValidTtl(options.ttlSeconds);

      const serialized = JSON.stringify(value);

      if (serialized === undefined) {
        throw new Error("Cache value cannot be serialized as JSON");
      }

      if (options.ttlSeconds === undefined) {
        await client.set(key, serialized);
      } else {
        await client.set(
          key,
          serialized,
          "EX",
          options.ttlSeconds
        );
      }
    },

    async delete(key: string): Promise<void> {
      assertValidKey(key);
      await client.del(key);
    }
  };
}

```

### Step 4 — `packages/redis/src/cache/index.ts`

```

} from "./create-json-cache.js";

```

Cache API behavior

| Method                                | Behavior                                               |
| ------------------------------------- | ------------------------------------------------------ |
| `getJson<T>(key)`                     | Returns parsed data or `null` on a cache miss          |
| `setJson(key, value, { ttlSeconds })` | Serializes JSON and applies an expiry                  |
| `delete(key)`                         | Removes the cache entry                                |
| Invalid JSON                          | Logs a warning, schedules eviction, and returns `null` |
| Invalid key or TTL                    | Throws a validation error                              |

A TTL is optional at the API level, but prefer TTLs for ordinary application cache entries. Persistent cache entries should be a deliberate decision.

```
export interface RedisHealthClient {
  ping(): Promise<string>;
}

export async function checkRedisHealth(
  client: RedisHealthClient
): Promise<"up" | "down"> {
  try {
    const response = await client.ping();
    return response === "PONG" ? "up" : "down";
  } catch {
    return "down";
  }
}

```

The health helper deliberately returns a small, predictable status. Your HTTP health endpoint can later convert this to your shared service-health response format.

## 5. Implement the Redis client and lifecycle

### Step 6 — `packages/redis/src/create-redis-client.ts`

```

import Redis from "ioredis";
import type { Logger } from "pino";

import { createJsonCache } from "./cache/create-json-cache.js";
import type { JsonCache } from "./cache/create-json-cache.js";
import { checkRedisHealth } from "./health/redis-health.js";

export interface CreateRedisClientOptions {
  url: string;
  logger: Logger;
  serviceName: string;
  connectTimeoutMs?: number;
  maxRetriesPerRequest?: number;
}

export interface RedisDatabase {
  client: Redis;
  cache: JsonCache;
  connect(): Promise<void>;
  healthCheck(): Promise<boolean>;
  close(): Promise<void>;
}

export function createRedisClient(
  options: CreateRedisClientOptions
): RedisDatabase {
  const {
    url,
    logger,
    serviceName,
    connectTimeoutMs = 5000,
    maxRetriesPerRequest = 3
  } = options;

  const client = new Redis(url, {
    lazyConnect: true,
    enableReadyCheck: true,
    connectTimeout: connectTimeoutMs,
    maxRetriesPerRequest,
    connectionName: serviceName,
    retryStrategy(times: number) {
      return Math.min(times * 200, 2000);
    }
  });

  let closing = false;
  let connectPromise: Promise<void> | undefined;
  let closePromise: Promise<void> | undefined;

  client.on("error", (err: Error) => {
    logger.error(
      { err, dependency: "redis", service: serviceName },
      "Redis client error"
    );
  });

  client.on("reconnecting", () => {
    logger.warn(
      { dependency: "redis", service: serviceName },
      "Redis client reconnecting"
    );
  });

  const connect = async (): Promise<void> => {
    if (closing) {
      throw new Error("Redis client is closing");
    }

    if (client.status === "ready") {
      return;
    }

    if (connectPromise) {
      return connectPromise;
    }

    connectPromise = (async () => {
      try {
        await client.connect();
        await client.ping();

        if (closing) {
          throw new Error("Redis client closed during connection");
        }

        logger.info(
          { dependency: "redis", service: serviceName },
          "Redis connection verified"
        );
      } catch (error) {
        connectPromise = undefined;
        throw error;
      }
    })();

    return connectPromise;
  };

  const healthCheck = async (): Promise<boolean> => {
    if (closing || client.status !== "ready") {
      return false;
    }

    return (await checkRedisHealth(client)) === "up";
  };

  const close = (): Promise<void> => {
    if (closePromise) {
      return closePromise;
    }

    closing = true;

    closePromise = (async () => {
      if (client.status === "ready") {
        await client.quit();
      } else {
        client.disconnect();
      }

      // A concurrent initial connection may have failed as we shut down.
      await connectPromise?.catch(() => undefined);

      logger.info(
        { dependency: "redis", service: serviceName },
        "Redis client closed"
      );
    })();

    return closePromise;
  };

  const cache = createJsonCache(client, logger);

  return {
    client,
    cache,
    connect,
    healthCheck,
    close
  };
}

```

## 6. Add unit tests

These tests verify the cache contract without needing Redis to be running.

### Step 8 — `packages/redis/tests/create-json-cache.test.ts`

```

import { describe, expect, it, vi } from "vitest";

import {
  createJsonCache,
  type RedisCacheClient
} from "../src/cache/create-json-cache.js";

function createFakeRedis() {
  const store = new Map<string, string>();

  const client: RedisCacheClient = {
    get: vi.fn(async (key) => store.get(key) ?? null),

    set: vi.fn(async (key, value) => {
      store.set(key, value);
      return "OK";
    }),

    del: vi.fn(async (key) => Number(store.delete(key)))
  };

  return { client, store };
}

function createLogger() {
  return { warn: vi.fn() } as never;
}

describe("createJsonCache", () => {
  it("returns null for a cache miss", async () => {
    const { client } = createFakeRedis();
    const cache = createJsonCache(client, createLogger());

    await expect(cache.getJson("product:123")).resolves.toBeNull();
  });

  it("serializes and reads JSON values", async () => {
    const { client, store } = createFakeRedis();
    const cache = createJsonCache(client, createLogger());

    const product = { id: "123", name: "Keyboard", price: 999 };

    await cache.setJson("product:123", product, { ttlSeconds: 60 });

    expect(store.get("product:123")).toBe(JSON.stringify(product));
    expect(client.set).toHaveBeenCalledWith(
      "product:123",
      JSON.stringify(product),
      "EX",
      60
    );

    await expect(
      cache.getJson<typeof product>("product:123")
    ).resolves.toEqual(product);
  });

  it("allows an explicit cache entry without a TTL", async () => {
    const { client } = createFakeRedis();
    const cache = createJsonCache(client, createLogger());

    await cache.setJson("reference:currency", { code: "INR" });

    expect(client.set).toHaveBeenCalledWith(
      "reference:currency",
      JSON.stringify({ code: "INR" })
    );
  });

  it("deletes cache entries", async () => {
    const { client, store } = createFakeRedis();
    const cache = createJsonCache(client, createLogger());

    store.set("product:123", '{"id":"123"}');

    await cache.delete("product:123");

    expect(store.has("product:123")).toBe(false);
  });

  it("rejects an empty key", async () => {
    const { client } = createFakeRedis();
    const cache = createJsonCache(client, createLogger());

    await expect(cache.getJson(" ")).rejects.toThrow(
      "Cache key must be a non-empty string"
    );
  });

  it("rejects a zero or invalid TTL", async () => {
    const { client } = createFakeRedis();
    const cache = createJsonCache(client, createLogger());

    await expect(
      cache.setJson("product:123", { id: "123" }, { ttlSeconds: 0 })
    ).rejects.toThrow("ttlSeconds must be a positive integer");
  });

  it("treats malformed JSON as a cache miss", async () => {
    const { client, store } = createFakeRedis();
    const logger = {
      warn: vi.fn()
    } as never;

    store.set("product:broken", "{invalid-json");

    const cache = createJsonCache(client, logger);

    await expect(cache.getJson("product:broken")).resolves.toBeNull();
    expect(logger.warn).toHaveBeenCalled();
  });
});

```

### Step 11 — Connect during service startup

Connect before accepting requests. This ensures the service knows whether Redis is available at startup.

```
import { redis } from "./redis/index.js";

async function startServer(): Promise<void> {
  await database.connect();
  await redis.connect();

  // Start your existing HTTP server here.
  // Example: app.listen(config.service.port, ...);
}

startServer().catch((error: unknown) => {
  logger.fatal({ err: error }, "Service startup failed");
  process.exitCode = 1;
});
```

This is a startup illustration, not a complete server lifecycle implementation. If startup fails after one dependency has connected, close already-open dependencies before exiting. We'll consolidate startup, readiness, signal handling, and shutdown in the later lifecycle phase.

### Step 12 — Use the cache

For example, in a Product or Order handler where caching is appropriate:

```
const cacheKey = "product:123";

const cachedProduct =
  await redis.cache.getJson<{ id: string; name: string }>(cacheKey);

if (cachedProduct) {
  return cachedProduct;
}

// Fetch the authoritative value from the appropriate database.
const product = {
  id: "123",
  name: "Mechanical Keyboard"
};

await redis.cache.setJson(cacheKey, product, {
  ttlSeconds: 300
});

return product;
```

The example demonstrates the cache API only; replace the placeholder database lookup with your real repository or service call. A cache miss must not be mistaken for a missing product in the database.

For cache invalidation, remove the corresponding key when a successful update changes the underlying data:

```
await redis.cache.delete("product:123");
```

For a multi-service system, use namespaced keys such as `product:123`, `order:456`, and `auth:session:...`. Avoid putting passwords, payment credentials, or other secrets into cache values or keys.

## 9. Verify against your real Redis container

After the package's typecheck and unit tests pass, verify the connection against the Redis instance already configured in your Docker Compose setup.

First, check that Redis is running:

```
docker compose ps
```

If your Redis service is named `redis`, inspect its health and logs:

```
docker compose logs --tail=100 redis
```

Then start the Order Service using its normal development command. Its startup logs should show that the Redis connection was verified.

You can also test Redis directly inside the container:

```
docker compose exec redis redis-cli PING
```

Expected response:

```
PONG
```

Test JSON serialization and expiry:

```
docker compose exec redis redis-cli SET phase14:test '{"status":"ok"}' EX 60
docker compose exec redis redis-cli GET phase14:test
docker compose exec redis redis-cli TTL phase14:test
docker compose exec redis redis-cli DEL phase14:test
```

Expected behavior:

- `SET` returns `OK`.
- `GET` returns the JSON string.
- `TTL` returns a positive number up to 60.
- `DEL` returns `1` if the key existed.

If authentication is configured, use your existing secure container configuration rather than exposing credentials in shell history.

### One architecture note before moving on

The client has reconnect behavior, but this does not guarantee that every Redis command will succeed during an outage. Cache callers should handle connection errors appropriately, and cache availability must not be allowed to compromise payment or order correctness.

Also, the current health check intentionally avoids a Redis call if the client isn't ready. For production readiness endpoints, wrap dependency checks in a bounded timeout so a stalled health check cannot hang the endpoint.
