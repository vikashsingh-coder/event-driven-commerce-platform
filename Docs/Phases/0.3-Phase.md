# Phase 0.3 — Shared Libraries Implementation

## Goal

Before building any microservice, we will create reusable internal packages.

In a real enterprise microservice architecture, every service should **not rewrite common functionality**.

Instead:

```text
                 Shared Packages


        --------------------------------

        |        |        |            |

     Auth    Product   Order       Payment


        --------------------------------
```

All services consume the same:

- Configuration system
- Logger
- Error handling
- Validation
- Database utilities
- Event system
- Security utilities
- Observability tools

# Package 1 — Config Package

## Purpose

Centralized environment configuration.

Every service needs:

- PORT
- DATABASE URL
- Redis URL
- RabbitMQ URL
- JWT secrets
- External API keys

Instead of:

```typescript
process.env.DATABASE_URL;
```

everywhere,

we use:

```typescript
config.database.url;
```

# Environment Schema

Create:

```
src/schema.ts
```

```typescript
import { z } from "zod";

export const envSchema = z.object({
  NODE_ENV: z
    .enum(["development", "production", "test"])
    .default("development"),

  PORT: z.string().transform(Number).default("4000"),

  DATABASE_URL: z.string().optional(),

  MONGODB_URL: z.string().optional(),

  REDIS_URL: z.string().optional(),

  RABBITMQ_URL: z.string().optional(),

  JWT_SECRET: z.string().optional(),
});
```

---

# Environment Loader

Create:

```
src/env.ts
```

```typescript
import dotenv from "dotenv";
import { envSchema } from "./schema";

dotenv.config();

const parsed = envSchema.safeParse(process.env);

if (!parsed.success) {
  console.error(parsed.error.format());

  process.exit(1);
}

export const env = parsed.data;
```
