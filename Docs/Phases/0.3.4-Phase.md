# Phase 0.3.4 — `@ecommerce/validation`

## 1. Goal

We want every service to follow the same flow:

```text
HTTP Request
     ↓
Validation Middleware
     ↓
Controller
     ↓
Service
     ↓
Repository
```

For example, instead of manually checking:

```typescript
if (!email) {
  ...
}

if (!password) {
  ...
}
```

we will define a schema:

```typescript
const loginSchema = z.object({
  email: z.string().email(),
  password: z.string().min(8),
});
```

and let the shared validation package handle it.

# 8. Validation Function

Create:

```text
packages/validation/src/validate.ts
```

```typescript
import type { Request } from "express";

import type { ZodType } from "zod";

import { ValidationError } from "@ecommerce/errors";

export function validateRequest<T>(schema: ZodType<T>, data: unknown): T {
  const result = schema.safeParse(data);

  if (!result.success) {
    throw new ValidationError(
      "Request validation failed",
      result.error.flatten(),
    );
  }

  return result.data;
}
```

This function gives us a reusable validation mechanism.

Example:

```typescript
const data = validateRequest(loginSchema, request.body);
```

# 9. Validation Middleware

Now create:

```text
packages/validation/src/middleware.ts
```

```typescript
import type { RequestHandler } from "express";

import type { ZodType } from "zod";

import { ValidationError } from "@ecommerce/errors";

import type { ValidationTarget } from "./types.js";

export function validate(
  target: ValidationTarget,
  schema: ZodType,
): RequestHandler {
  return (request, _response, next) => {
    const result = schema.safeParse(request[target]);

    if (!result.success) {
      next(
        new ValidationError(
          "Request validation failed",
          result.error.flatten(),
        ),
      );

      return;
    }

    request[target] = result.data;

    next();
  };
}
```

# 10. Important TypeScript Issue

Express's `Request` properties such as:

```typescript
request.body;
request.query;
request.params;
request.headers;
```

have different types.

Because of that, assigning:

```typescript
request[target] = result.data;
```

may cause TypeScript errors depending on the Express version and inferred schema type.

A cleaner production implementation is to avoid mutating the request object directly.

We can instead store validated data in `request.locals`.

However, Express does not provide a strongly typed `locals` property on `Request` by default.

So for this project, we'll use a dedicated symbol-based storage.

---

# 11. Better Validation Storage

Replace `middleware.ts` with:

```typescript
import type { RequestHandler } from "express";

import type { ZodType } from "zod";

import { ValidationError } from "@ecommerce/errors";

import type { ValidationTarget } from "./types.js";

export const VALIDATED_DATA = Symbol("validatedData");

export function validate(
  target: ValidationTarget,
  schema: ZodType,
): RequestHandler {
  return (request, _response, next) => {
    const result = schema.safeParse(request[target]);

    if (!result.success) {
      next(
        new ValidationError(
          "Request validation failed",
          result.error.flatten(),
        ),
      );

      return;
    }

    const validated = (request as any)[VALIDATED_DATA] ?? {};

    validated[target] = result.data;

    (request as any)[VALIDATED_DATA] = validated;

    next();
  };
}
```

This keeps validated values separate from raw request values.

# 12. Helper to Read Validated Data

Add to:

```text
packages/validation/src/validate.ts
```

```typescript
import type { Request } from "express";

import type { ValidationTarget } from "./types.js";

import { VALIDATED_DATA } from "./middleware.js";

export function getValidatedData<T>(
  request: Request,
  target: ValidationTarget,
): T {
  const data = (request as any)[VALIDATED_DATA]?.[target];

  return data as T;
}
```

import { getValidatedData } from "@ecommerce/validation";

export async function loginController(request, response) {

# 22. Why Not Just Use `request.body`?

Because we want a clear distinction:

```text
request.body
     ↓
Untrusted input


validated body
     ↓
Validated input
```

This becomes particularly useful in security-sensitive services such as:

```text
Payment Service
Order Service
Authentication Service
```
